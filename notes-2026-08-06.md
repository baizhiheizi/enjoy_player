Why this forward step:

- Issue #527 (an-lee, 2026-08-05) is a research issue with a clear recommended direction but stops short of pinning the decision. ADR-0070 turns that recommendation into a concrete architectural record.
- The data-only Phase 2 is already in draft PR `repo-assist/ipa-phase2-word-timings-2026-08-05`; this ADR specifies the *Phase 1* implementation work that the Phase 2 PR unblocks.
- Captures five concrete decisions:
  1. **Hybrid IPA source**: `open-dict-data/ipa-dict` static wordlists for the 9 focus/display locales (license-audited: MIT / CC-BY / CC-BY-SA only; CC-BY-NC entries dropped) + a batched LLM phonemizer endpoint on the Worker for OOV and the four lookup tags ipa-dict does not ship (`it-IT, pt-BR, pt-PT, ru-RU`).
  2. **No new local phonemizer engine** (no Dart port of eSpeak, no GPL bundle in the app, no alignment engine in Phase 1).
  3. **Purely additive data model**: `TranscriptWord.ipa?: String`. No Drift migration (`timeline_json` is opaque TEXT, same pattern as ADR-0039's `sourceKey`).
  4. **Cache topology**: Worker KV `(locale, word) -> ipa` as L2 / source of truth, local Drift mirror as L1. Reuses ADR-0045's two-tier AI result cache fingerprinting shape.
  5. **Renderer**: word-segmenting span builder in `transcript_markup.dart` runs only when `words != null`; existing selection math stays valid. Default off, gated by a Settings toggle.
- **Phasing in/out-of-scope** is explicit: in-scope (data model + static dict + Worker endpoint + KV + Drift mirror + renderer + toggle + license audit/attribution); out-of-scope (alignment engines, eSpeak, on-device phonemizer, OOV negative-cache, Phase 3 phone-level timing).
