## Task 8 (Performance Improvements)

- Identified that `_camelToSnakeToken` and `_snakeToCamelToken` in `lib/data/api/case_conversion.dart` allocate one single-char `String` per iteration via `input[i] + c.toLowerCase()`. The recursive key walkers fire on every `ApiClient` request and response, so non-trivial bodies with hundreds of keys allocate heavily in the JSON-encode hot path.
- Replaced with a direct `codeUnitAt(i)` walk that folds ASCII uppercase / lowercase inline via `StringBuffer.writeCharCode`. Non-ASCII keys (code ≥ 0x80) fall back to the original `input[i].toLowerCase()` path so they keep their previous Unicode-aware shape.
- Added a regression test that locks in the non-ASCII behaviour (`caféName`, `naïve`).
