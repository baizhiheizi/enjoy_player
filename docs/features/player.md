# Feature: Player

## MVP behavior

- `PlayerController` owns playback via injectable `PlayerEngine` (production: `MediaKitPlayerEngine` wrapping a single `mk.Player`, ADR-0003). Open flow is split for clarity:
  - [`resolvePlaybackOpen`](../../lib/features/player/application/playback_open_resolver.dart) — loads rows + `PlayableSource`, throws `MediaNeedsRelocateException` when needed.
  - [`ensureEngineForPlayableSource`](../../lib/features/player/application/player_engine_binding.dart) — swaps MediaKit vs YouTube engine and bumps `playerEngineRevProvider`.
  - [`schedulePlayerOpenSideEffects`](../../lib/features/player/application/player_open_side_effects.dart) — cloud transcript fetch + recording pull when signed in.
  - [`VideoPosterCaptureService`](../../lib/features/player/application/video_poster_capture_service.dart) — optional JPEG poster capture + Drift thumbnail update.
- Restores position + echo flags from `echo_sessions`.
- Debounced persistence via `PlaybackSessionPersister`; embedded subtitle discovery via `EmbeddedTrackSync`.
- `PlayerUi` tracks chrome mode (mini vs expanded) for expand/collapse side effects; route `/player/:id` still drives most visible chrome. Playing/buffering come from `playerIsPlayingProvider` / `playerIsBufferingProvider` (stream providers over the engine, each seeded with `Player.state` so the transport bar matches the engine immediately after route changes).
- Re-opening `/player/:mediaId` while that media is already the active session does **not** call `openUri` again.
- **Video library poster**: when a `VideoRow` has no `http(s)` `thumbnail_url` and no readable local thumbnail file, after open `VideoPosterCaptureService` may capture a JPEG via `PlayerEngine.screenshot` (`image/jpeg`) and write `media_thumbs/<key>.jpg`, then patch Drift (see `library.md`). Remote artwork URLs are never overwritten. If the temporary seek used to grab the frame fails to restore back to position zero afterward, that failure is logged at **WARNING** with the grep-friendly message `video poster capture failed to restore seek-zero position` (previously a nested empty `catch` silently swallowed it).
- **Synced local-only media**: Playback resolution is **local-first**: a trusted `localUri` (size/mtime) wins over `mediaUrl`. If this machine has no trusted file at `localUri` and the row has a content fingerprint (`md5` column — SHA-256 hex), opening the player shows **Locate media file**. The user picks the same file; the app links or copies it only when the hash matches, then updates `localUri` / trust metadata and enqueues a sync update. See [ADR-0050](../decisions/0050-path-linked-local-media.md).
- **Sandboxed macOS — security-scoped bookmarks**: On the macOS App Sandbox build, the implicit `NSOpenPanel` grant only lasts for the current process. Every externally linked import / re-locate captures a `URL.bookmarkData(options: .withSecurityScope, …)` blob (stored in `videos.bookmark_data` / `audios.bookmark_data`); every open re-resolves it and calls `startAccessingSecurityScopedResource()`, releasing the grant when the next `open()` or engine `dispose()` fires. Requires the `com.apple.security.files.bookmarks.app-scope` entitlement. See [ADR-0080](../decisions/0080-macos-security-scoped-bookmarks.md).
- **Engine swap (ADR-0057)**: When switching YouTube ↔ MediaKit, `ensureEngineForPlayableSource` installs the new engine and bumps `playerEngineRevProvider` **before** disposing the old one so `PlayerSurfaceHost` can drop the prior platform view. It then **waits for the old surface to detach** (bounded) and a short native-settle delay before `prepareNativeBackend()` allows MediaKit to construct `mk.Player`. Old-engine `dispose` is **fire-and-forget** — awaiting YouTube `closeStreams` held the loading skeleton for the full 5 s command timeout on a 4 s local file (2026-08-30). Position-tracker listeners are cancelled before the swap so that teardown is not blocked by a still-subscribed stream. If `engine.open` still times out after a swap, the coordinator **retries once** with a fresh MediaKit engine. Post-open commands (subtitle disable, prefs, restore seek) are bounded and degrade on timeout so they cannot hold the skeleton. The **first local/URL open** also installs `MediaKitPlayerEngine` and bumps so the host can mount `Video` before decode.
- **Local video surface (ADR-0057)**: MediaKit creates `VideoController` when the on-screen `Video` stage builds — not from `warmVideoSurface` (that bound a native texture with no widget and left Windows/Android black). The stage fills the host slot (`BoxFit.contain`). After the texture id/rect exist, and again when the viewport jumps (loading 16:9 → side-by-side chrome), the stage pulses `Video` width/height so libmpv presents. Local loading claims the same `player.expanded` target as chrome so that swap cannot unmount the texture. Desktop uses software output (`hwdec: auto-safe`, `enableHardwareAcceleration: false`). MediaKit is omitted while the host is parked (`keepSurfaceWhenParked == false`); YouTube WebView stays mounted. [`PlayerSurfaceTarget`](../../lib/features/player/presentation/widgets/player_surface_target.dart) reports geometry after layout **and** paint so the host follows the target when size is unchanged.
- **Modals above the surface (ADR-0065 / ADR-0066)**: Enjoy helpers (`showEnjoySheet` / `showEnjoyDialog` / `showEnjoyAlertDialog` / `showEnjoyAdaptiveSheet`) default to `useRootNavigator: true` so dialogs and sheets clear the permanent host in the Flutter tree. Independently, [`PlayerSurfaceOverlayCoordinator`](../../lib/core/player/player_surface_overlay_coordinator.dart) parks the host for every `PopupRoute` (navigator observers on root + shell) and for `AppNotice` snackbars — required on Windows where WebView2 can paint above Flutter overlays. YouTube parks by **translation only** (keeps the last on-screen stage size); shrinking the WebView to 320×180 was the play-then-pause stimulus after every CC-sheet round-trip (m.youtube.com treats 320 px as a compact-player breakpoint and flushes ABR). In-stage chrome stays on host `overlayBuilder`; competing WebView routes (`/youtube/login`) also use `forcePark`. Prefer Enjoy helpers / `AppNotice` over raw snackbars on player paths.
- **Desktop MouseTracker safety**: [MouseRegion] `onEnter`/`onExit` handlers that rebuild UI (hover chrome, cards, transport) must defer via [`runOutsideMouseTracker`](../../lib/core/interaction/mouse_tracker_safe.dart). Parking/moving the WebView under the cursor otherwise re-enters `MouseTracker._deviceUpdatePhase` and floods debug logs with `!_debugDuringDeviceUpdate`.
- **Shell**: `EnjoyBottomNav` on compact widths, `AppSidebar` from ~900px; nav chrome is hidden on `/player/*` for focus. There is **no** collapsed mini player ([ADR-0082](../decisions/0082-home-continue-no-mini-player.md)); leaving `/player/` clears the live session (except vocabulary clip practice). Resume from Home **Continue practicing** or by opening the item again.
- **Content layout** (`VideoPlayerLayout`, [ADR-0059](../decisions/0059-phone-tablet-orientation-and-player-aspect-layout.md)): video and transcript are **side-by-side** when the player layout is **landscape** (`width > height`), and **stacked** (16:9 stage over transcript) in **portrait or square** — including wide portrait tablets. This is **not** gated on `breakpointTranscriptSideBySide` (720); that token remains for transport-bar packing. Draggable split: transcript column min **360** logical px (capped at 50% width); split width is **persisted** in player preferences (`splitPx`). Transcript panel uses a subtle **1px** left border on the zinc surface; video stage is letterboxed on black with **top SafeArea** padding on the stacked layout. **Tap the local video stage** to toggle play/pause (same affordance as YouTube’s embedded player); YouTube taps stay on the WebView and are not intercepted. Host chrome overlays (`MouseRegion` above the permanent surface) use `opaque: false` so empty regions pass hits through to the WebView while title-bar / share / open-in-browser controls remain clickable.
- **Orientation policy** ([ADR-0059](../decisions/0059-phone-tablet-orientation-and-player-aspect-layout.md)): phone-class devices (shortest side &lt; 600 logical px) lock to portrait app-wide; tablet-class devices may auto-rotate; desktop windows stay freely resizable.
- **Expanded video**: the frosted collapse control stays top-left while playing (same persistence as the YouTube account cluster at bottom-right). Title + scrim show only when **paused or buffering**. YouTube login / open-in-browser sit **bottom-right on the stage** and only for YouTube media (`supportsYouTubePlayback`). No reserved `AppBar` height — overlay chrome does not shift the 16:9 stage. **Expanded audio** has **no** AppBar and no reserved strip — the **same frosted collapse control floats top-left over the transcript**, which scrolls under its blur (desktop adds a `space32` top inset for optical balance) ([ADR-0085](../decisions/0085-audio-floating-collapse-chrome.md)). Title stays in the transport bar.
- Echo enforcement uses `lib/features/player/domain/echo_window.dart` (ported from web). The two enforcement paths — the reactive per-tick correction and the proactive seek clamp — are serialized through a single [`EchoEnforcer`](../../lib/features/player/application/echo_enforcer.dart) coordinator (one in-flight seek/pause at a time, so they can't interleave into a stutter). Enforcement runs on every position event so the segment-end pause-and-rewind fires within ~50 ms of the boundary; the in-memory session + DB write stay on the 400 ms bucket. Echo tick correction is itself a pure function — see [Decision reducers (D1–D10)](#decision-reducers-d1d10) below.

### Decision reducers (D1–D10)

Inline transport decisions live as **pure-function reducers** in [`lib/features/player/domain/transport_decisions.dart`](../../lib/features/player/domain/transport_decisions.dart), following the precedent set by [`decideEchoPlaybackTime` / `EchoPlaybackDecision`](../../lib/features/player/domain/echo_window.dart). Each reducer takes only its inputs and returns a sealed-class result; side effects (seek/play/emit/log) stay in the single imperative consumer that `switch`es over the sealed type. Keeping the logic out of widget / controller methods means every branch is unit-tested without a running engine.

| # | Reducer | Returns | Consumer | Purpose |
|---|---------|---------|----------|---------|
| D1 | `decideSeekRouting({echoActive})` | `SeekRoutingDecision` (`throughEcho` / `direct`) | `PlayerController.seekTo` | Route user seeks through the single-flight `EchoEnforcer` when echo is active so a user seek can't interleave with reactive per-tick enforcement. |
| D3 | `decideReplayTarget({echoActive, echoStartTimeSeconds, activeLineStartSeconds})` | `ReplayTargetDecision` (`echoStart(time)` / `lineStart(time)`) | `PlayerInteractions.replayLine` | Replay jumps to the echo window start when echo is active, otherwise to the line containing the current time. |
| D4 | `decideProgressSeekTime({fraction, durationSeconds})` | `ProgressSeekDecision` (`valid(time)` / `invalid`) | `PlayerInteractions.seekFromFraction` | Convert a `[0,1]` strip drag into a clamped seek target; `invalid` when duration is zero / unknown. |
| D5 | `decideYouTubePlayRestart({playbackCompleted})` | `YouTubePlayRestartDecision` (`restart` / `resume`) | `YoutubePlayerEngine.play` | Reload the watch page when the previous play completed; otherwise issue JS `play()`. |
| D6 | `decidePollTransition({jsEnded, jsPaused, playing, pausedPollStreak, pauseConfirmThreshold, playbackCompleted})` | `PollTransitionDecision` (`MediaJustEnded` / `PauseStreaking` / `PollPlaying` / `PollIdleTick`) | `YoutubeWebviewPollLoop` | Reduce the raw JS poll tick + session state into the next transport transition, including streak-based pause confirmation. |
| D7 | `decideOnMediaEnd({repeatMode})` | `MediaEndDecision` (`stop` / `loop` / `loopSegment`) | `CompletionLoop._run` | Maps `RepeatMode.{none,single,segment}` to the next action consumed by the deterministic completion loop (see ADR-0044 below). |
| D10 | `decidePlaybackRateStep({rate, direction})` | `PlaybackRateStepDecision` (`ValidRateStep(rate)` / `FloorRateStep(rate)` / `CeilingRateStep(rate)`) | playback-rate hotkey command (`player.slowDown` / `player.speedUp`) | Reduce a `shift+comma` / `shift+period` nudge to the next playback rate within 0.25–2.0; the clamped `rate` is applied even at the floor / ceiling (issue #719). |

When adding a new transport decision, put it in `transport_decisions.dart` next to its neighbours; do **not** branch inline in the controller or engine. Companion unit tests live in [`test/features/player/transport_decisions_test.dart`](../../test/features/player/transport_decisions_test.dart) (one test per branch, including the `EchoClamp` / NaN-guard cases for `decideEchoPlaybackTime`).

- **Deterministic end-of-media handling (ADR-0044)**: `PlayerEngine.completed` is surfaced through both engines (MediaKit forwards mpv's `completed`; YouTube synthesizes from the `<video>` `ended` event / poll loop at ~250 ms resolution). [`CompletionLoop`](../../lib/features/player/application/completion_loop.dart) — owned by `PlayerController` — is the **single consumer** of that event and of the repeat policy: a deterministic await-completion loop guarded by a `_playbackGen` counter (same pattern as `EchoEnforcer._epoch` / `_openGeneration`) so duplicate, late, or stale `completed` events are no-ops. The YouTube poll loop only *surfaces* the end transition (mark completed, stop polling, emit transport state) and never decides a repeat action itself. The loop reads its next action from `decideOnMediaEnd` (D7 above):
  - `none` → `StopAtEnd` (media is at the end; user can press play to restart).
  - `single` → `LoopMedia` (seek to zero, play, re-await — loops the whole file).
  - `segment` → `LoopSegment` (seek to echo window start, play, re-await — only when echo is active; falls back to `none`).

## Presentation

- **Global transport** — composed from [`presentation/widgets/transport/`](../../lib/features/player/presentation/widgets/transport/) (progress strip, volume popover, artwork/meta, CC, fullscreen, play ring). [`GlobalTransportBar`](../../lib/features/player/presentation/widgets/global_transport_bar.dart) mounts only on `/player/:id` ([ADR-0082](../decisions/0082-home-continue-no-mini-player.md)) as an **inset floating glass capsule** (rounded `GlassSurface`, same language as [`EnjoyBottomNav`](../../lib/core/theme/widgets/enjoy_bottom_nav.dart)). `RootShell` mounts it as `Scaffold.bottomNavigationBar` with `extendBody` and a transparent scaffold so the capsule floats over transcript the same way the tab bar floats over pages. Native video/YouTube stays in the upper `PlayerSurfaceTarget` stage; [ADR-0066](../decisions/0066-park-player-surface-for-overlays.md) parks that surface for overlays, not for this bar. Playback speed opens an **Enjoy** bottom sheet (`showEnjoySheet` + drag handle) rather than a stock `PopupMenuButton`. Collapse, back, or any other navigation off `/player/` flushes persistence then `PlayerController.clear()` (vocabulary clip practice excepted).
- **Line-level transport** — previous line, next line, replay line, and echo mode are disabled when there is no primary transcript (empty or still loading); the echo button stays enabled while echo mode is active so the user can exit echo without transcript lines. On **narrow layouts** (≤720px), the four practice controls — **play/pause, echo, subtitle (cc), speed** — are always shown and never dropped for width; **blur/hide** is in the CC subtitle sheet (wide/desktop still shows blur on the bar); **replay** is omitted from the bar (tap the active transcript line or use hotkeys). When width is still tight, controls drop in the order **previous → next → volume** (previous before next, both before volume; previous and next are independently droppable because tapping a transcript line also jumps). The desktop-video fullscreen button is the highest-priority droppable (last to drop). The visible control set is computed by the pure [`resolveNarrowTransportBudget`](../../lib/features/player/presentation/widgets/global_transport_bar.dart) function from the live width (LayoutBuilder), so it updates immediately on rotation/resize.
- **Expanded player** — [`ExpandedPlayerChromeBody`](../../lib/features/player/presentation/expanded_player_widgets.dart) + loading/error bodies; YouTube account affordance uses [`playerYoutubeLoginChromeSupportedProvider`](../../lib/features/player/application/player_engine_capabilities_provider.dart) so UI does not depend on concrete engine types. Local video uses [`playerEngineProvider`](../../lib/features/player/application/player_engine_provider.dart) for the active engine (same instance as the controller’s engine, including test doubles).

## Engine contract (ADR-0015, ADR-0057, #720)

The player seam has three layers, each with one job (issue #720):

1. **`PlayerEngine`** — the *transport* contract. Position / duration / playing / buffering / completed streams, the open/seek/play/pause/setRate/setVolumeNormalized/playOrPause/stop/warmVideoSurface/dispose commands, plus the swap-lifecycle hooks (`awaitSurfaceReady`, `awaitSurfaceDetached`, `prepareNativeBackend`, `resetCompletionFlag`, `teardownAfterClear`) and `keepSurfaceWhenParked`. Everything the player surface or the open path must call on every engine regardless of kind. The contract carries no `media_kit` types.

2. **Capability interfaces** in [`player_engine_capabilities.dart`](../../lib/features/player/application/player_engine_capabilities.dart) — what only *some* engines can do:
   - `PosterCapture` (frame capture for stored thumbnails) — MediaKit only; the YouTube WebView shot captures HTML chrome, not the composited video frame, so it renders as a solid black rectangle.
   - `SubtitleTrackControl` (disable rendered subtitles + the embedded track list) — MediaKit only; YouTube has no libmpv track list to clear. The `media_kit` `Tracks` type now lives behind this capability, not on the transport contract.
   - `YoutubePlaybackEngine` (marker: this engine plays YouTube sources through the WebView). Replaces the old `supportsYouTubePlayback` boolean.
   - `PlayerEngineMetadata` (poster plumbing, current source identity, open-timing instrumentation) — YouTube only; MediaKit renders decoded frames and has nothing to preload.
   Call sites branch with `engine is PosterCapture` etc., never on concrete classes. Presentation also reads [`playerEnginePlaysYoutubeProvider`](../../lib/features/player/application/player_engine_capabilities_provider.dart) instead of the engine type tag.

3. **`EngineSwapCoordinator`** — the *swap choreography*: install + bump, surface-detach wait, wedged-engine replacement, open-retry ladder, and the swap-in-flight latch (issue #657). One owner; `PlayerController` wires it on construction; `PlayerOpenHost.engineSwap` exposes it to the open coordinator. `PlayerController.warmYoutubeSurface` uses `coordinator.install` without `discardWithoutAwaiting` so the "must never dispose a live/parked engine" rule holds by construction.

The video stage remains a **presentation** concern: [`PlayerSurfaceHost`](../../lib/features/player/presentation/widgets/player_surface_host.dart) maps the active engine identity to a per-engine stage (`MediaKitVideoStage` / `YoutubeVideoStage`) through [`buildPlayerVideoStage`](../../lib/features/player/presentation/widgets/player_stage_resolver.dart) (issue #664). Engines publish the non-widget inputs their stage reads (`nativeBackendAllowed` + `videoController` for MediaKit; `session` / `webViewLifecycle` for YouTube) and are notified of stage layout through `noteStageViewportSize` so the park/refocus policy stays with the transport code. Keeping the long-lived single `InAppWebView` (no `Key` by `videoId`) still works because the whole stage slot is keyed by engine identity (ADR-0057) — the WebView ordering constraints are unchanged.

**Engine-kind erasure (issue #595)** is preserved across the split: the only places that name a concrete engine class are the stage widgets + resolver, the YouTube WebView host, the engine construction sites (`PlayerController` / `EngineSwapCoordinator.ensureEngineForPlayableSource` / `EngineSwapCoordinator.replaceWedgedLocalEngine`), and `MediaKitVideoStage` / `YoutubeVideoStage` reading the non-widget inputs published above. The resolver's downcast — `engine is MediaKitPlayerEngine` / `engine is YoutubePlayerEngine` — is sanctioned here in player.md (not in ADR-0057, which constrains only *who* hosts the stage); issues #595 and #664. The `media_kit` `Player` is still constructed only inside `MediaKitPlayerEngine` (ADR-0003 / ADR-0015).

## Fullscreen (desktop)

- The transport bar shows a fullscreen toggle button for video on Windows/macOS/Linux. The button is hidden for audio and on non-desktop platforms.
- F11 (customizable) also toggles fullscreen when a video session is active.
- Pressing Escape while fullscreen exits fullscreen first; a second Escape then pops the route/dialog as normal.
- Collapsing the expanded player (via the back arrow or `Ctrl+Shift+P`) also exits fullscreen automatically.

## Position quantization (single source of truth)

`lib/features/player/application/position_buckets.dart` consolidates the three position quantization buckets into named constants. Do not inline these values in feature code — the per-bucket split keeps the transport scrubber responsive while the transcript highlight avoids per-tick rebuilds that flood the Windows accessibility bridge (flutter/flutter#182444). See `quantized_position.dart` for the dedup behavior.

| Constant | Value | Used by |
|----------|------:|---------|
| `kPositionBucketSessionEmitMs` | 400 | In-memory `PlaybackSession` + debounced DB write cadence — one update per 400 ms bucket so the recorded clip window lines up across runs. Echo *enforcement* itself runs on every position event (see `EchoEnforcer`); only the heavy session emit is gated to this bucket. |
| `kPositionBucketDisplayMs` | 400 | Time display + transcript active-line highlight — 400 ms matches human-perceptible cue changes |
| `kPositionBucketScrubberMs` | 50 | Transport scrubber position updates — finer bucket keeps the slider tracking finger drags without regressing accessibility |

## Open / close behavior

- **`PlayerController.openMedia`** catches exceptions from `engine.open` and any downstream awaits so a failed open does not leave `state` pointing at a phantom session. The player surfaces the error to the existing failure path (`AsyncValue.error`) rather than masking it with stale session metadata.
- **`PlayerController.clear()`** flushes the pending `PlaybackSessionPersister` write **before** cancelling the debounce timer, so a swipe-to-dismiss does not lose the last ~450 ms of position updates. Tests for the persister should cover the "dismiss while debounced write is queued" case explicitly.
- **Media-switch flush in `runPlayerOpen`**: opening new media flushes the previous session's pending `PlaybackSessionPersister` write **before** the new media's echo/blur restore overwrites the live providers — otherwise a stale debounce/max-age timer would fire afterwards and write the new media's echo window + blur flag into the old media's row (issue #653). Pinned by the "persister hand-off" group in `test/features/player/application/player_open_coordinator_test.dart`.
- **`PlayerController` reentrancy-guarded disposal**: a `_disposed` flag protects `dispose()` from re-entrant calls, and the native (mpv) teardown future is captured as an observable `teardown` getter so callers (tests, a future logout flow) can await disposal completion. Riverpod's `ref.onDispose` is not awaited, so an explicit `ref.invalidate` of `playerControllerProvider` could race a double-mpv disposal without this guard. See [`teardown`](../../lib/features/player/application/player_controller.dart) and `_disposed` field.
- **Position durable write mid-playback**: [`PlaybackSessionPersister`](../../lib/features/player/application/playback_session_persister.dart) coalesces updates on a 450 ms debounce, but forces an immediate flush when pending data is older than ~2 s (`kMaxPendingWriteAge`). This bounds data loss on crash/kill to ~2 s regardless of playback rate, rather than the rate-dependent window that existed when the debounce re-armed on every 400 ms session emit without a max-age ceiling.
- **Pre-navigation warm-up is generation-guarded (issue #657)**: [`PlayerController.warmYoutubeSurface`](../../lib/features/player/application/player_controller.dart) is the speculative pre-install called from Home / Library / Discover tiles **before** navigating to `/player/`. It now bails unless the controller is genuinely idle — not disposed, no live session (`state == null`), no open in flight (`_openInFlight`) — and only installs a YouTube engine when nothing is owned. A live or parked MediaKit engine is kept in place (engine swaps belong to the open path, where they are generation-coordinated by `ensureEngineForPlayableSource`, ADR-0057); tapping a YouTube tile during local playback no longer disposes mpv outside the open path, which used to wedge media_kit's native event pump process-wide.
