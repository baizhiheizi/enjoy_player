# Enjoy Player v0.10.4

A feature release that adds dictation practice under the Dictate lens, keeps
craft text edits safe from unrelated state updates, and makes the craft
history and library date labels an order of magnitude cheaper to render.

## Dictation practice: listen, then prove it

The Dictate lens is now a full practice loop, not just hide-and-peek. The
looped line's words stay masked while you listen, then you prove you
understood them in one of two ways:

- **Voice retell** — record with `R`; your take is transcribed and every
  word is compared against the original.
- **Text** — type what you hear, with a live word-count progress line.

After checking, the line reveals an inline word-level diff — correct,
missed, or extra — plus an accuracy percentage. Try again resets the
attempt, Next line moves on, and every attempt is kept under "Previous
dictations" for the line. Voice retells persist as regular shadow-reading
takes, so they replay and score exactly like echo takes, and entering
Dictate arms a one-line loop on the active cue — the loop is what hosts
the practice card (#1308).

## Craft text fields keep in-progress edits

The Advanced and Express craft text fields could lose the draft and cursor
when an unrelated state update landed mid-edit. External updates now wait
until the field loses focus instead of replacing the text under the user,
and explicit actions (Re-translate, Regenerate, Use translated text)
release focus so their new value appears immediately — even on touch
devices (#1294).

## Faster date labels

The craft history tiles and the library's relative-day labels built a fresh
date formatter on every row rebuild. The formatter is now constructed once
per locale: a 502-row pass drops from 3.0–4.6 ms to 0.13–0.17 ms on the
craft path, and from 0.70–0.76 ms to under 0.13 ms on the relative-day
path, with identical output (#1299).

## The lookup credits header stops over-fetching

Every loaded-section rebuild of the lookup sheet invalidated the credits
summary unconditionally, so one display plus five same-result rebuilds
fired seven live balance calls for a number that had not moved. The
refresh is now deduped per section by the result token: a same-result
rebuild refreshes nothing, a fresh result refreshes exactly once
(7 fetches → 2) (#1258).

## Also in this release

- Build reliability: all four platform build workflows retry `flutter pub
  get` with pub.dev when the China mirror serves a stale archive, the
  sqlite3 native-library prefetch survives a 504 from GitHub's release CDN
  with an API-endpoint fallback, and the Drift-backed tests carry a
  five-minute budget on shared runners (#1269).
- Internal consolidations with no user-visible change: the auto-translate
  controller splits into a testable scheduling queue plus a picker-provider
  module (#1295); the transcript line tile splits into text and chrome
  modules (#1284); the craft tools' paste fields and busy labels share two
  widgets, fixing a missing mounted guard in the translate paste path
  (#1283); the REST list endpoints share one `listResource` helper (#1274);
  the cloud library body splits into focused part files (#1302); and the
  transcript skeleton row plus the auth callout each collapse to one
  implementation (#1307).
- The dependency set moves forward within the existing constraints —
  flutter_riverpod 3.5.0, sqlite3 3.9.0, build_runner 2.17.1 and
  companions; no constraint is widened and nothing is added or removed
  (#1269).
- The 2026-11-06 docs-drift review findings are resolved (#1268).
