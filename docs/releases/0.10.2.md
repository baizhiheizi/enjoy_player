# Enjoy Player v0.10.2

A patch release that makes the macOS build start again, and ships the fixes
collected since v0.10.1.

## If you are on v0.10.1 (macOS), download this release by hand

The v0.10.1 macOS build could not start at all: it died in the dynamic
linker before the app opened, so it never reached the update check.
**A v0.10.1 install cannot update itself.** Download v0.10.2 again from
[player.enjoy.bot](https://player.enjoy.bot) and replace the old app.

Only the macOS direct download was affected — Windows, Linux, Android and iOS
builds were fine.

## The macOS build starts again

The macOS bundle shipped a library that the app needed but never included.
The bundler only followed dependencies whose path started with
`/opt/homebrew/`, but a relocatable Homebrew keg names its own dependencies
by `@rpath` — so `libbrotlidec.1.dylib` shipped while the
`libbrotlicommon.1.dylib` it needs was left behind. The app then died in dyld
before `main()` on every launch.

The bundler now follows `@rpath` references against the keg they came from,
gives every bundled library `@loader_path` so it resolves inside the app
bundle, and **fails the build** when any load command in any Mach-O does not
resolve. The macOS release also starts the signed app before the zip is
packed, so a bundle that cannot launch can no longer be published at all
(#1096, #1097, #1098, #1099).

## Also fixed

- **Windows and Linux release builds ship their installers again** (#1077).
  On a tag push the installer step was skipped while the upload step still
  required it, so v0.10.0 and v0.10.1 shipped without an installer. The flag
  now compares the event explicitly, and the Linux AppImage download retries
  instead of dying on a single TLS reset.
- **The Synthesize and Translate panels show the same failure surface** (#1081).
  The two Advanced-tool panels carried their own inline failure trees, which
  had drifted from the shared card and had dropped the sign-in and
  open-AI-settings actions. Both now offer the same actions.
- **A release publishes only its own notes** (#1088). The release body fell
  back to the whole `CHANGELOG.md`, so a release without a hand-written notes
  file would have published every version's notes at once. It now publishes
  `docs/releases/<version>.md`, or the matching `CHANGELOG.md` section.

## Also in this release

- **Transcript timelines re-scan about 20x faster** (#1071): the transcript
  revision key counted a 1–10 MB payload rune by rune, three times per
  revision tick. The count is now a linear scan, and the revision is derived
  once per row instead of three times.
- **The README, the landing page, and every store screenshot are redrawn in
  the Duet design language** (#1079), and a CJK glyph bug that fell back to a
  Latin font in the screenshot gallery is fixed.
- **YouTube artwork in the library uses the high-resolution 16:9 variant**
  (#1078), and the home recents and library screens now share one artwork and
  badge implementation.
- The landing page now deploys through Cloudflare Pages' Git integration, and
  the `youtube_session.dart` source splits into focused part files with no
  change in behaviour (#1093).

## Upgrade

Download from [player.enjoy.bot](https://player.enjoy.bot). Existing installs
pick up the new version through the in-app update check — except for macOS
v0.10.1 installs, which have to be replaced by hand as described above.

Full details are in the [CHANGELOG](https://github.com/baizhiheizi/enjoy_player/blob/main/CHANGELOG.md).
