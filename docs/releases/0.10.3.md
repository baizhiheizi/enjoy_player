# Enjoy Player v0.10.3

A patch release that ships the Windows and Android builds again, and makes the
signed-in start and the transcript noticeably faster.

## Windows and Android ship again

The v0.10.2 tag produced the macOS and Linux artifacts but failed its Windows
and Android release jobs: both runners run the full test suite, and five cases
failed there for platform reasons rather than product ones — two design guards
compared raw paths with `/` separators, so their Windows exemptions never
matched; one media-analysis case expected a POSIX path back from
`Uri.toFilePath()`; the pre-v6 migration guard left the failing database open,
so Windows could not delete its temp directory; and the expanded-player
thumbnail test read an autoDispose provider without a listener, so it could be
disposed between reads.

All five now pass on their own runners, so this release carries the Windows
installer and the Android bundle and sideload APKs (#1123).

## Faster signed-in start

Resolving the locale, the learning language, the native language and the theme
mode happens before the app renders its router, so those four reads sit on the
signed-in cold-start critical path. They were four separate queries against the
settings table; they are now one query, with each value still resolved through
its own codec and still falling back to its declared default (#1124).

## Faster transcript

The familiar-form IPA was derived from scratch every time it was asked for —
once per word of a row on every row rebuild, once more per word for the "does
this row have phones" boolean, and once per line across the whole transcript
while the transcript scans for display readiness. The derivation is now
memoized per word, and the readiness scan stops as soon as its flags are known
(#1127).

## Also in this release

- The dependency set moves forward within the constraints the project already
  set — no dependency is added, removed or given a wider constraint (#1125).
- The eSpeak-NG synthesizer in the forced-alignment package splits into five
  focused modules, with no change to its public API or its behavior (#1135).
- The 2026-10-28 documentation review findings are resolved, and a design
  guard now rejects Material's `SegmentedButton` in `lib/` (#1130, #1131,
  #1133).
