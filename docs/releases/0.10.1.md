# Enjoy Player v0.10.1

A patch release that restores YouTube playback on macOS, Windows, iOS, and Android.

## YouTube playback is fixed on every platform except Linux

v0.10.0 shipped a regression from #972 (the Linux-only frame-stall probe). The probe's
platform predicate was wired into the WebView **host mount** gate instead of the probe
itself, so the `InAppWebView` never mounted on any platform but Linux. `onWebViewCreated`
never fired, the JS channel stayed null, and every play command short-circuited with
"youtube play ignored without WebView" (issue #1033).

The mount gate is back to availability + mount request, and the probe's platform support
now gates the probe alone — the Linux-only sampling scope and the 900 ms → 15 s backoff
cadence from #972 are unchanged. A new test asserts the host mounts on every playable
platform and that the probe starts on Linux only.

**If YouTube playback was broken in v0.10.0, this release fixes it.**

## Also fixed

- **The relative-day label stays correct across a DST transition** (#1015). `relativeDayLabel`
  measured the gap between two local midnights, but on a spring-forward day those midnights
  are only 23 hours apart — the day count truncated to 0, so yesterday rendered as "today".
  The count is now measured between UTC midnights, which are always exactly 24 hours apart.
- **Secure storage works on the macOS direct-download build again** (#1048, issue #1044).
  The Developer ID build signs without a keychain access group, so the macOS data-protection
  keychain was unreachable and BYOK API keys could not be saved at all. Every macOS build now
  stores its secrets in the legacy keychain, and the cold-start profile cleanup no longer
  logs a false "secure storage delete failed" error. A BYOK key saved by a local macOS build
  has to be entered once.
- **Closing a screen mid-action no longer breaks the action** (#1046). Several actions read
  Riverpod providers after an await, so closing the screen while a Discover subscribe, a
  media-language save, a library import, a cloud-library add, or a craft recording was in
  flight threw a disposed-ref error — the save was reported as failed and the library list
  kept stale data. The provider reads now happen before the await.

## Also in this release

Internal refactors with no user-visible change: the media registry, sync queue job, and
release publish scripts split into focused modules, the videos/audios DAOs share one
single-row write path, the sync upload service shares one entity-upload recovery path, and
the dictionary sense renderer is shared between lookup and flashcards.

Documentation: the 2026-10-21 docs-drift review findings are resolved, and the repo-assist
agent prompt no longer hardcodes the Flutter version.

Download from [player.enjoy.bot](https://player.enjoy.bot). Existing installs pick up the

the app's update dialog.
