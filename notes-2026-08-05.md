## Task 8 — Performance Improvements: bundled image-cache PR

Branch `repo-assist/perf-image-network-cache-2026-08-05`, commit `1bddded`. 3 files / +11 / -8.

- **`lib/features/discover/presentation/discover_channel_avatar.dart`** — public widget used in subscription rows, filter strips, and recommended channel cards. `Image.network(url!, ...)` → `Image(image: CachedNetworkImageProvider(url!), ...)`.
- **`lib/features/discover/presentation/discover_feed_tile.dart`** — same swap inside the private `_VideoThumbnail` and `_ChannelAvatar` rendered in the Discover SliverGrid feed card (lines 285 and 422).
- **`lib/features/player/presentation/widgets/youtube_video_poster.dart`** — same swap. The `_useMqFallback` post-frame retry path is unaffected — the provider swap only changes the image-resolution cache, not the error pipeline.

Why:
- Discover feed renders many thumbnails and avatars. Flutter's built-in `ImageCache` holds decoded bitmaps briefly but does not persist across cold starts, so every launch refetches and re-decodes the same thumbnails.
- `cached_network_image` (already a project dep — `^3.4.1` in `pubspec.yaml`) caches bytes to disk AND keeps decoded bitmaps around longer. Same pattern already in use at `sidebar_account_chip.dart` line 78.
- Behavior is preserved: same `Image` widget, same `errorBuilder` / `loadingBuilder` callbacks. Existing `youtube_video_poster_test.dart` (which asserts on `find.byType(Image)`) keeps passing without edits.

Why `Image(image: CachedNetworkImageProvider(...))` instead of `CachedNetworkImage`:
- Preserves the existing widget tree; no widget-substitution churn, fewer test edits.
- Lets the existing `errorBuilder` retry logic in `youtube_video_poster` keep working unchanged — `CachedNetworkImageProvider` invokes the same `ImageStream` error path.
